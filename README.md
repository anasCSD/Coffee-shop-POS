# Coffee Shop POS ☕

A modern, responsive Point of Sale (POS) and inventory management system built with **Flutter** and **Supabase**. Designed for coffee shops and cafes, featuring live sales tracking, menu management, shopping cart, and comprehensive daily/monthly sales reports with PDF and CSV export capabilities.

---

## 🚀 Features

### ☕ Menu & Catalog Management
- **Live Menu Synchronization**: Real-time inventory loaded directly from Supabase.
- **Full Item Lifecycle**: Add new items, edit existing item details, or toggle active/inactive status.
- **Dynamic Category Filtering**: Horizontally scrollable category chips automatically generated from your active catalog (Hot Coffee, Cold Coffee, Bakery, etc.).
- **Instant Search**: Search items by name with instant filtering and clear action.

### 🛒 Point of Sale & Cart
- **Fast Cart Operations**: Quick add from item cards, real-time quantity adjustments, item removal, and grand total computation.
- **Multiple Payment Methods**: Support for Cash, Card, and Mobile Banking.
- **Server-Side Integrity**: Sales are transacted atomically via Supabase database functions (`record_sale`), ensuring consistent totals and line items.
- **Visual Badges**: Dynamic cart quantity badge in both the top bar and drawer.

### 📊 Live Dashboard & Drawer Navigation
- **Real-Time Today's Stats**: Displays live **Today's Sales** (SAR) and **Items Sold** count, automatically refreshing after checkouts.
- **Slide-out Navigation Drawer**: Clean navigation sidebar providing access to Cart, Sales Reports, Menu Management, and Logout.
- **Consistent SAR Currency**: Standardized currency display (Saudi Riyal - SAR) across all screens, receipts, and reports.

### 📈 Sales Reports & Data Export
- **Daily & Monthly Reports**: Switch between daily and monthly views with integrated date pickers.
- **Payment & Item Breakdowns**: Detailed breakdown of revenue by payment method and sales volume per item.
- **One-Click Export**:
  - 📄 **PDF Report**: Formatted tables using `pdf` ready to print or share.
  - 📊 **CSV Report**: UTF-8 encoded with BOM for compatibility with Microsoft Excel and Google Sheets.

### 🔐 Authentication
- **Secure Access**: Powered by Supabase Auth with an `AuthGate` stream builder that automatically transitions between the login screen and POS dashboard based on session state.

## ⚙️ Setup & Configuration

### 1. Configure Supabase Credentials
Create a file named `config.json` in the root of the project (this file is git-ignored for security):

```text
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_PUBLISHABLE_KEY=your-supabase-publishable-key
```

> **Note**: Never expose your Supabase `service_role` key in client applications. Use only the `anon` / `publishable` key.

### 2. Database Schema (Supabase SQL)
Run the following SQL script in your Supabase SQL Editor to set up the necessary tables and functions:

```sql
-- 1. Items Table
create table if not exists public.items (
  id bigint generated by default as identity primary key,
  name text not null,
  category text not null,
  price numeric(10, 2) not null check (price >= 0),
  is_active boolean not null default true,
  created_at timestamp with time zone default timezone('utc'::text, now()) not null
);

-- 2. Sales Table
create table if not exists public.sales (
  id bigint generated by default as identity primary key,
  total_amount numeric(10, 2) not null check (total_amount >= 0),
  payment_method text not null check (payment_method in ('cash', 'card', 'mobile_banking')),
  created_at timestamp with time zone default timezone('utc'::text, now()) not null
);

-- 3. Sale Items Table
create table if not exists public.sale_items (
  id bigint generated by default as identity primary key,
  sale_id bigint references public.sales(id) on delete cascade not null,
  item_id bigint references public.items(id) on delete set null,
  item_name text not null,
  quantity integer not null check (quantity > 0),
  subtotal numeric(10, 2) not null check (subtotal >= 0),
  created_at timestamp with time zone default timezone('utc'::text, now()) not null
);

-- 4. Record Sale Atomic RPC Function
create or replace function public.record_sale(
  p_items jsonb,
  p_payment_method text
)
returns bigint
language plpgsql
security definer
as $$
declare
  v_sale_id bigint;
  v_total numeric(10, 2) := 0;
  v_item record;
  v_db_item record;
  v_subtotal numeric(10, 2);
begin
  -- Calculate total based on server prices
  for v_item in select * from jsonb_to_recordset(p_items) as (item_id bigint, quantity int) loop
    select name, price into v_db_item from public.items where id = v_item.item_id;
    if not found then
      raise exception 'Item with ID % not found', v_item.item_id;
    end if;
    v_total := v_total + (v_db_item.price * v_item.quantity);
  end loop;

  -- Insert sale master record
  insert into public.sales (total_amount, payment_method)
  values (v_total, p_payment_method)
  returning id into v_sale_id;

  -- Insert sale line items
  for v_item in select * from jsonb_to_recordset(p_items) as (item_id bigint, quantity int) loop
    select name, price into v_db_item from public.items where id = v_item.item_id;
    v_subtotal := v_db_item.price * v_item.quantity;

    insert into public.sale_items (sale_id, item_id, item_name, quantity, subtotal)
    values (v_sale_id, v_item.item_id, v_db_item.name, v_item.quantity, v_subtotal);
  end loop;

  return v_sale_id;
end;
$$;
```
